# V30 postmarketOS

**简体中文** | [English](README.en.md)

面向 LG V30 US998 的非官方、实验性 postmarketOS 集成项目与重建说明，默认进入认证 TTY，本机按方向自动横竖屏。

本项目建立在 **postmarketOS、Linux 和 ShapeShifter499 的 V30 主线移植工作**之上。IMS 协议与媒体实现来自 **Catcrafts imsd**。我们的新增工作包括组件集成、开机顺序、每次通话的音频资源管理与清理、短信持久化、来电提醒与铃声音量、通话记录和常驻通知、普通音量与蜂窝状态栏、部分互操作修复，以及限定范围的验证。上游贡献与许可证信息见[致谢](ACKNOWLEDGEMENTS.md)和[来源记录](PROVENANCE.md)。

**验证结论仅适用于具体版本与测试范围。** 历史 r35/r36 结果来自一台使用中国联通网络的 US998。主机端的重建／打包检查与实机观察分别记录；部分 r37/r38 用户空间变更及后续修订的范围见下文。完整公开源码尚未在干净设备上重新完成端到端部署；上游 PR 对应的独立候选尚无实机验收。Ready for review 仅表示 PR 已进入可评审阶段，不代表上游接受或实机验收通过。

我们的已完成工作及其上游基础集中记录在[贡献说明](docs/contributions.md)中；服务器稳定性、振铃与显号、短信完善及后续验证工作见 [TODO／路线图](TODO.md)。每项待办均附验收条件，在取得证据前保持未完成状态。其他项目文档以英文为主。

## 最新实机进展

本地默认系统已集成 r81。TTY 跟随手机方向切换并保留原会话，LVGL 触控面板和 USB-C 外屏均按需启动。实测涵盖横竖屏两端留白、面板转屏与触控、1080p 外屏和键鼠、录音回听，以及真实来电号码居中和中文短信滚动三遍。一次普通重启确认方向服务自启及 IMS 自动注册。

公开构建说明目前仍以早期基线为入口。后期实现以源码和验收摘要提供，完整 r81 干净安装仍待复验。下文的早期外显记录按当时基线阅读。

## 来电与通知

r37 为横屏 TTY 增加以下功能：

- 来电振铃、自动亮屏和显号；缺失或不安全的号码显示为 `Unknown/withheld`，结束后清除当前来电行。
- 铃声音量可设为 0–100%，默认 60%，状态栏显示 `RING 60%`；0 为静音，来电仍可亮屏显号。
- 本地持久通话记录，区分已接、未接、拒接及证据不足的未知状态。
- `MISSED n   SMS n` 常驻计数，保留到相应标记被显式处理，不随当前来电行过期。

```sh
sudo v30-phone ring-volume
sudo v30-phone ring-volume 100
sudo v30-phone history --missed
sudo v30-phone history --missed --mark-read
sudo v30-sms list --unread
sudo v30-sms read ID
```

只查看通话列表不会清除通知；`--mark-read` 仅清除本次列出记录的标记，保留历史。读取短信会清除其本地未读标记，不会自动回复。音量百分比控制下一次来电的有限幅度铃声，不表示通话音量或实际声压。部署时将提醒模块、媒体包装器、状态栏、命令和配置一起安装，详见[来电、音量、记录和通知说明](docs/incoming-alerts.md)。默认方案保留正常登录认证和蓝牙关闭，不自动接听或拨号。

## 音量与蜂窝状态栏（r38）

- **`RING` 铃声音量：** 已在验收设备保存为 100%，用于下一次来电；通用配置示例仍默认 60%。百分比控制有限幅度的铃声，不改变通话增益。
- **`VOL` 普通扬声器音量：** 仅读取 ALSA 播放控制值；实机 8/15 显示为 53%，不代表实测声压。
- **`CELL` 当前运营商：** 使用当前注册网络的名称，名称为空时回退到网络代码；已检查联通 `UNICOM` 显示。
- **`NET` 当前网络制式：** 使用基带当前报告，实机显示 `4G LTE`。解析器可识别 2G/3G/4G/5G 报告，但 V30 硬件最高支持 4G，不具备 5G 能力。
- **`SIG` 信号状态：** 四格与质量百分比；旧读数保留最后格数并标注 `STALE`，缺失读数显示 `???? --`，搜索或无服务状态明确显示。

保留纯 TTY 横屏、正常登录认证、蓝牙关闭以及常驻未接来电／未读短信通知，最多占用五行状态栏。实机已检查 120 列画面、服务健康和保护文件；新增六项测试使 Linux root 测试总数达到 63 项。没有重新做 100% 铃声听验、语音／短信或重启验收。实现、输入能力说明与验证范围见[状态栏说明](docs/console-status.md)及 [r38 验证记录](provenance/r38-validation.json)。

## 紧凑状态栏与按需图形会话（r39）

TTY 常态布局缩为两行，保留已有指标；来电时才增加临时来电行。固定中文标签显示“联通 4G”、充电／未充、音／铃和未接／短信；Wi-Fi 与蓝牙明确显示 ON／OFF。电量、普通音量和铃声音量去掉百分号，信号保留阶梯格数与质量百分比，过期值仍明确标注。字形按原生 24×48 像素绘制；TTY 的这些固定中文标签不等于完整中文字体或输入法。

当前实验图形会话采用 Weston／Pixman 普通内存影子缓冲、软件 Xwayland、GTK3 启动页、Openbox、XTerm 和 Onboard／UIM 拼音。通过 `sudo v30-gui start` 手动进入，使用 Return to TTY 或 `sudo v30-gui stop` 退出；默认仍为有登录认证的横屏 TTY、蓝牙关闭，暂存须显式加 `--desktop`，不启用开机显示管理器。原生竖屏 Xorg 版本的触控和中文输入已通过人工测试，但快速输入延迟和花条未解决，合并刷新回调也因横向花条被否决并撤下。原生 Phoc／Pixman 自动重绘仅约每秒 3 帧，亦已停止。当前 Weston 路径沿用已验证的输入组件，自动重绘中位间隔约 33 毫秒，独立中文读回和一次退出／清理检查通过；随后人工验收仍见短暂横向花条，输入上屏和按键反馈慢一拍，该候选亦未通过，不能称为稳定图形桌面。独立 r40 显示诊断内核已完成两次独立授权 RAM 启动：第一次的 138 次采样的翻转通知均提前到传输结束前约 10 毫秒，但软件重绘中位间隔仍约 33.55 毫秒。第一次测试窗口内用户不在场；随后另行授权的第二次 RAM 实测确认横向花条和输入延迟仍在，r40 候选未通过，不能称为修复。两次测试后均恢复未改写的 r35 默认系统、IMS 和服务器服务。后续直接 Xorg/KMS 的替代路径也被人工验收否决。r42 连续 DSI 时钟候选完成编译和审计后进行了一次独立授权 RAM 实测，但用户反馈黑屏，已否决并恢复 r35 默认和服务。轻量 GTK3 键盘替代 Onboard 后，用户确认点击响应明显改善，但花条更频繁；整窗重绘也未解决。随后官方 libdrm `modetest` 仅翻转两个预填充缓冲区、完全绕过 GTK/Xorg/键盘，用户仍观察到横向花条，已自动回到正常 TTY。下一步集中核对 DRM/DPU/DSI/DSC/面板链路，原厂 SCR1 与当前 pre-SCR 参数差异已完成源码计算对照，但 r46 一次独立授权 RAM 彩条实测仍见同样花条，候选未通过、未进入 GUI，已恢复默认系统及蜂窝／IMS／服务器服务；见[显示排查记录](docs/display-investigation.md)。依据与范围见 [r41/r42 记录](provenance/r41-r42-display-validation.json)。内屏 GUI 为原生竖屏，默认 TTY 保持横屏。详见[按需图形会话](docs/manual-desktop.md)。

2026-11-01：用户将偶发花条评估为不影响使用的轻微体验问题，暂缓排查并保留为已知限制。图形界面按需使用，不作为便携服务器／TTY 工作流的核心依赖；默认继续为有认证的横屏 TTY、蓝牙关闭。这不代表花条已修复。

当前优先推进 USB-C 外接显示器，再测试 Phosh／Plasma Mobile 及资源开销。r48 通过 PD 能力发现；r49 因 SVID／节点错误和不安全的 DRM 动态解绑被否决，已恢复默认。修正后的 r50 已完成一次 RAM 实测：AOC 进入 DP 模式、读到有效 EDID，一次约 20 秒的 1080p60 静态图完整稳定，用户确认手机横屏 TTY 正常；随后普通重启回 r35，IMS／全部 11 个服务／原有档案和保护哈希通过核验，授权已关闭。首次有线静态出图通过；其启动时依赖等待和日志告警仍保留，自动加载的后续结果见 r51。默认系统尚未集成外接输出；按需桌面、重复热插拔、4K 和新内核通话兼容仍未通过，详见[外接显示器进度](docs/external-display.md)。

2026-11-02：r51 的一次 USB2 RAM 验收已结束并关闭授权。复用 r50 内核／DTB／模块的集成镜像自动加载五项提供者，manual modprobe=0，横屏 TTY、蓝牙关闭和 GUI 不自启通过。最初 GUI 请求因 sysfs 模式缓存缺少1080p被错误拒绝，可信只读 DRM probe 后确认有效 EDID256／1080p60；已删除两行过早预查，旧源码和 once 保留。随后唯一实际外屏 GUI 虽有 Weston／Xwayland／GTK 进程及 DP1080p60／DSI关闭状态，用户看到的却是手机白屏、显示器蓝屏、没有鼠标，物理验收失败；另外两个窗口未运行。进程清理后的 tty1 状态不能证明物理恢复。之后普通重启回 r35/r30，用户确认正常横屏 TTY，IMS／全部11服务／档案与保护哈希均通过，授权关闭。生产 r30 电话守卫未改，默认外屏仍未集成。

r51 的完整时间线在 GUI 前已出现 DPU CTL flush 超时，不能把 DSI关闭认定为已证根因。之后另行授权的一次 r52 RAM 对照保留 DSI `current`、将软件 Xwayland 定向 DP-1：有限 legacy `modetest -v` 完成至少540次真实翻帧，DP VSYNC计数994→1362→1637，无新增DPU错误，DSI保留；用户确认彩条／纯色交替符合测试预期且TTY正常。第一个双输出 GUI 窗口的物理画面、输入、中文和 Return to TTY 获用户确认，清理、混音器、四PCM及tty8恢复通过。软件PNG只证明应用渲染，物理交互通过来自用户反馈。

第二个 r52 GUI 已 active 时，用户从 AOC 拔线接回 Mac，看到 LG logo；手机实际重启回 r35/r30，主控制器未执行默认切换脚本。拔线回TTY验收失败，根因未知；pstore已挂载但空，RAM boot在logbook无记录，不能据此判定panic、watchdog、电源或驱动原因。默认全量健康、IMS／全部11服务、原2短信4通话内容及SQLite、保护哈希和物理横屏TTY通过，授权已关闭；部署中的《诗经》和 logbook 数据库（包含 live WAL）额外只读 quick_check 均通过；未做全业务内容比较。公开 runtime 仍是被否决的 r51 单输出原型，私有 r52／r53／r54 配置和诊断入口尚未合入，不能把安装本仓库等同获得这些结果。r52不推广默认；详见[r52有界记录](provenance/r52-dual-output-validation.json)。

r53 随后完成一次独立授权的无GUI legacy plain-buffer翻帧／拔线对照：拔线门禁前至少240次真实完成事件、DP IRQ进展、DSI保留且无新增显示错误；整个流中共61批、至少3660次完成事件。用户确认AOC稳定灰色、拔AOC后TTY正常，但插Mac后重启，主控制器没有请求默认重启。因此GUI不是复现重启的必要条件，原因仍未知。独立Wi-Fi保存5352条连续内核记录，无缺号／overrun；捕获到正常PHY关闭后旧1280×1024缓存模式被错误重新启用，软件已禁用的AUX返回`-6`，link返回`-104`，随后DPU超时。这是具体显示路径问题，尚不能认定为reset原因。

r53重启后默认r35/r30全量健康、IMS／全部11服务、原2短信4通话内容／SQLite、业务库结构检查（含WAL）及保护哈希通过；40项手机证据已归档校验，授权关闭，未导出SQLite或做全业务内容比较。见[r53有界记录](provenance/r53-legacy-detach-validation.json)。

r54 随后完成一次新授权 RAM 实测，仅修改一个 fbdev helper 的六行顺序：先处理 pending hotplug，再恢复缓存模式。唯一 legacy 窗口至少2640次真实翻帧，拔AOC观察3秒再接Mac后仍为同一RAM启动，无新增显示错误，通过。第一个双输出GUI的物理画面／输入／中文及手动ReturnTTY、exit0和完整清理通过；终端字距偏大仍待r55验证修订。手机在外屏GUI期间显示背景是该配置设计，不是内屏scanout质量证明。

第二个r54 GUI仅拔下AOC、尚未接Mac的3秒内就重启，用户和独立USB／Wi-Fi均确认已回默认；拔线自动返回仍失败。20834条连续kmsg无缺号，末尾仅见DP关闭后新的atomic-check资源预留，没有完成硬件重启用／link training或panic记录，提交者和重启原因未知。六行修补通过了legacy旧缓存顺序对照，没有修好GUI热拔，不推广默认。默认r35/r30全量健康、IMS／全部11服务、原2短信4通话内容／SQLite、业务库只读结构检查（含WAL）、源／保护／runlevel／boot／recovery哈希均通过；drm.debug恢复0，49项手机证据已下载逐hash验证，授权关闭，无通话／发短信／分区写入。r56复用r54镜像的caller kprobe及Weston实时流仅做离线可行性准备，没有新RAM／GUI授权。默认仍是认证横屏TTY、蓝牙关闭、GUI不自启；Phosh／Plasma随后。见[外接进度](docs/external-display.md)、[按需图形会话](docs/manual-desktop.md)及[r54有界记录](provenance/r54-fbdev-hotplug-validation.json)。

| 蓝牙策略 | 已测试的本地配置中蓝牙保持关闭 | 此策略需明确选择启用；新打包的最终关闭服务仅经过主机端检查 |
